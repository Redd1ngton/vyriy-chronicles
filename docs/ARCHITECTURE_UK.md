# Вирій v0.2 — фактична архітектура та правила

Цей документ замінює v0.1. Стару специфікацію перенесено до `archive`; твердження про загін, 99 рівнів чи попередній Job Level більше не описують поточну гру.

## Стан продукту

Один завершуваний регіон з трьома з’єднаними зонами: слобода → ліс → катакомби → повернення. Локальний режим опубліковано; авторитетний Node-сервер кооперативу з SQLite включено у репозиторій і перевірено, але не розгорнуто на публічному сервері. Це не масове MMORPG із загальним світом і акаунтами.

## Чому Phaser

Попередній клієнт не мав React: тільки DOM і власний Canvas renderer. Інтерфейс лишився HTML/CSS, а сцена замінена на Phaser 3.90. Phaser відповідає за GPU/Canvas малювання, текстури, кадри спрайтів, камеру, клавіатуру/вказівники, ефекти й масштабування. Колізії навмисно не довірені клієнтському Arcade Physics: спільне логічне ядро перевіряє їх однаково локально й на сервері. Проєкція ізометрична, координати симуляції — звичайні world x/y.

## Межі модулів

| Каталог | Відповідальність |
|---|---|
| `content/classes.js` | Класи, навички, ефекти, спеціалізації |
| `content/region.js` | Регіон, зони, планування, вороги, предмети, взаємодії |
| `content/atlas.js` | Перевірені межі кадрів атласів |
| `core/rules.js` | Чисті розрахунки, предмети, колізії, BFS, видимість |
| `core/simulation.js` | Авторитетна симуляція, AI, каст/снаряди, нагороди, голосування |
| `core/storage.js` | Локальний формат v2, перевірка імпорту, міграція v1 |
| `render/scene.js` | Phaser-сцена, глибина, камера, кадри, телеграфи |
| `ui/app.js` | Меню, HUD, клавіші дій, джойстик, налаштування |
| `net/client.js` | Локальна/мережева сесія, підтвердження, повторні повідомлення |
| `server/index.js` | HTTP/WebSocket, сесії, SQLite, транзакційна ідемпотентність |

Додати зону можна через дані ZONES: size/spawn/palette/roads/water/walls/houses/floorRooms/objects/enemies. Модулі рендеру й симуляції використовують однакові дані. Для нового специфічного типу інтерактивного об’єкта потрібен handler; додавання ще однієї скрині/пастки/порталу/ворога не змінює рушій.

## Один герой і прогрес

Вибір класу на старті. Початковий рівень 1, кап 85; початково 5 вільних очок; кожен новий рівень +5. Максимум окремої характеристики 99. XP до наступного рівня: `65+35L+floor(1.5L²)`.

STR/AGI/VIT/INT/DEX/LUK взято з попереднього проєкту. Наведені нижче коефіцієнти — робочі правила v0.2, не раніше погоджений баланс RO. Старі Job Level/Job XP у цій версії замінені рівневими спеціалізаціями. У міграції зберігаються Base рівень першого героя, досвід, Zeny, вкладені характеристики й підтримувані речі; оригінальний JSON v1 не змінюється.

Професійні розгалуження:
- 20: перша навичка отримує splash по сусідніх цілях або дає 1 с ухилення.
- 40: перша навичка сповільнює ворога або вбивство повертає 8 SP.
- 60: періодичне лікування союзників поруч або додаткова регенерація SP під час руху поза автобоєм.
- 85: друга навичка додатково дає щит, перша повертає 5 SP. Це фінальна механічна форма; окремого нового персонажного атласу ще немає.

Класи мають власні назви гілок; поведінкові модифікатори спеціалізацій спільні. Повністю окремі нові набори здібностей кожної підпрофесії — наступна ітерація, не завершена функція.

## Бойові формули

```text
MaxHP = 130 + 19L + 10VIT + gearHP
MaxSP = 55 + 3L + 4INT
meleeATK = 14 + 3L + 2STR + gearATK
rangedATK = 14 + 3L + 2DEX + gearATK
MATK = 15 + 3L + 2.3INT + gearMATK
DEF = (1.1VIT + gearDEF) × exposedMultiplier
MDEF = INT + gearMDEF
HIT = 85 + L + 1.3DEX
FLEE = L + 1.3AGI
CRIT = min(.30, .025+.0025LUK)
intervalSeconds = classPeriod / (1+.012AGI+.002DEX)
variableCast = max(.12, baseCast/(1+.006DEX))
hitChance = clamp((85+HIT−FLEE)/100, .15, .97)
damage = max(1, round(ATK×100/(100+DEF)×skillPower×critical))
critical = 1.5 or 1
```

MATK/MDEF замінюють ATK/DEF для магії. Blessing множить ATK/MATK на 1,2; exposed DEF ×0,75; guard incoming damage ×0,6. Runes +3 ATK/+3 MATK належать конкретному екземпляру зброї. Базова якість підтримана полем quality, але крафт/посилення ще не додано.

Влучання перевіряється для базових атак; активні навички не мають додаткового RNG miss. Будь-який снаряд усе одно повинен дістатися точки влучання: якщо ціль відійшла більш ніж на 1,25 клітини, попадання скасовується. Повторна перевірка дистанції й прямої видимості виконується перед завершенням касту. Прямого прострілу крізь стіни немає. Колізія польоту перевіряється по променю від початку до кінця.

### Початкова модель балансу

Показники рівня 1 зі стартовою зброєю проти DEF/MDEF 15; DPS — теоретичні звичайні атаки, включно з математичним очікуванням криту, без промахів, часу зближення, лікування й навичок.

|---|---:|---:|---:|---:|---|
| Мечник | 229 | 70 | 0,99 | 36,9 | Ближній бій, guard |
| Маг | 199 | 98 | 1,37 | 32,0 | Дальній каст, AoE, slow |
| Лучник | 199 | 70 | 1,13 | 35,0 | Дальність 6, root/poison trap |
| Послушник | 219 | 98 | 1,32 | 33,0 | Лікування союзника, blessing |
| Коваль | 239 | 74 | 1,15 | 31,9 | Shield союзникам, stun AoE |
| Злодій | 189 | 70 | 0,71 | 43,1 | Коротка дистанція, мала витривалість, leech |

Це не доведена рівність ефективності. Потрібні playtests часу проходження, витрат зіль та цінності підтримки. На старті навмисно немає безумовного переможця за HP/DPS/дальністю одночасно. Револьвер має необмежені базові набої; навички витрачають SP. Перезарядження магазину ще не реалізовано.

## Ефекти: коли спрацьовують і завершуються

| Ефект | Типова тривалість | Правило |
|---|---:|---|
| Отрута | 6 с | Щосекунди, до 3 stacks, оновлює left; не скидає таймер тіку |
| Slow | 5 с | Рух ×0,6; один stack, оновлення часу |
| Root | 2 с | Рух заборонений, атаки можливі; бос імунний |
| Curse | 7 с | Вхідне лікування ×0,5; один stack |
| Exposed | 5 с | DEF ×0,75; один stack |
| Guard | 6 с | Вхідна шкода ×0,6; один stack |
| Shield | 8 с | Пул 45+3INT, споживається шкодою; новий щит замінює пул |
| Might / Blessing | 9 с | ATK/MATK ×1,2; один stack |
| Evasion | 2 с | Звичайна шкода 0; не захищає від телеграфів і poison |
| Leech | 7 с | Повертає 25% фактично завданої прямої шкоди; не від poison |
| Stun | 1,4 с | Забороняє рух/початок навички/атаки; бос імунний |

Повторне накладання одиночного ефекту оновлює час, не додає множники. На завершенні left≤0 запис видаляється. Shield також завершується при вичерпанні пулу. Смерть скидає рух/каст; при відродженні всі стани очищаються. Іконки показують час і stacks, дотик відкриває повні пояснення; наведення не використовується.

## Світ, рух і видимість

BFS по 4 сусідах для однакової вартості тайлів; сервер і клієнт беруть однакові footprint будинків, води, дерев, стін та замкнених ґрат. Клавіатурний/джойстиковий рух перевіряє чотири точки кола радіуса 0,19; крок часу ≤0,1 с запобігає стрибкам крізь вузькі перешкоди. Перевірка променя виконується для цілей, взаємодій і снарядів. Перекат теж проходить через move, не телепортує крізь стіну.

У катакомбах існує лише floorRooms+roads; порожній простір непрохідний. Шлях до боса перекритий, поки не опущено важіль. Ліс/слобода мають дерева з детермінованими collision cells, а не лише декоративні малюнки. Крони, що закривають героя, стають напівпрозорими. Туман затемнює невидиму підлогу; scenery лишається як орієнтир, вороги за межею sight/стіною не відтворюються та не вибираються. Це не повноцінна система освітлення чи серверна anti-wallhack фільтрація: мережевий snapshot наразі містить усіх ворогів кімнати.

Карта — інформаційна панель. Перехід можливий лише при взаємодії з входом у самій зоні. Печатки, пастки, скрині, NPC, важелі, приховані ніші й вівтар мають окремі handlers.

## Вороги й боси

Росинка — ближній повільний противник; вовк — швидкий переслідувач; кажан — рухлива ближня ціль; кістяний лучник відступає, коли герой надто близько; гриб кидає отруйні спори; відьма накладає прокляття; дракон стріляє вогнем. Вони мають різні силуети та кадри атаки.

Поле ai='flank' у кажана наразі використовує швидке переслідування, а не окремий обхідний pathfinding — це явне спрощення. Вороги рухаються з axis collision, але ще не будують складних маршрутів обходу всіх перешкод. Статичні патрулі не реалізовані.

Дубовий вартовий: велетенське дерево, позначає майбутній розлом на землі на 2,1 с; після 50% HP застосовує кільце із безпечною серединою й викликає кажанів. Хранитель катакомб: окремий лицарський силует, така сама базова система телеграфів плюс печатка захисту, що зменшує пряму шкоду на 80%, поки гравці не взаємодіють зі стовпом. Після смерті причина поразки показує конкретний удар/отруту/невихід із позначеної зони. Катакомби мають вхід, коридори, альтернативні кімнати, пастку, секрет, важіль, боса, персональну скриню, вівтар-завершення й вихід.

## Мережевий протокол

HTTP створює/приєднує персонажа з classId+name; сервер генерує hero ID та випадковий recovery token. Клієнт не імпортує локальні Zeny/предмети/статистики в мережеву сесію. WebSocket передає лише intents: `move`, `steer`, `target`, `attack`, `skill`, `interact`, `stat`, `spec`, `equip`, `buy`, `sell`, `socket`, `use`, `ready`, `vote`, `offer`, `offerAccept`, `respawn`.

Кожна команда має operation_id і round. Сервер перевіряє право сесії, стан героя, ресурс/перезарядження, ціль, дистанцію, LOS, власність і вимоги. Перехід збільшує round; команди старої зони відхиляються. Стан і кожна подія мають монотонний eventSeq. Перепідключення отримує актуальний snapshot; непідтверджені наміри можуть бути відправлені повторно без подвійного виконання ресурсної операції.

Симуляція сервера 10 Hz, клієнтське відтворення до 60 FPS, інтерполяція координат. Повні snapshots зараз передаються кожні 100 мс, тому сервер не розрахований на масове публічне навантаження. Наступне технічне покращення — delta replication, interest management і розділення регіонів між процесами.

Готовність потрібна для колективних подій. Голосування фіксує список учасників, предмет рішення, yes/no, 20 с строк. При рівності голосів вирішує зафіксований лідер; відсутній до deadline голос рахується проти. Перехід переносить усіх гравців кімнати, очищує снаряди/шляхи, скидає готовність. Нові учасники під час голосування не змінюють electorate. Після від’єднання лідера роль отримує перший онлайн-гравець.

## Власність, передача й збереження

Кожен предмет `{id,template,owner,quality,card?}`; template містить name/kind/requirements/stats/description. Спорядження посилається на ID екземпляра. Порівняння підміняє слот у копії героя та обчислює derive(after)−derive(before), включно з картою. Не можна одягти чужий або непридатний за класом/рівнем предмет.

Персональний лут видається кожному живому онлайн-гравцеві в радіусі 14 клітин. Claim `enemySpawnId:heroId` унеможливлює повторну видачу за того самого ворога; respawn створює новий ID. Скрині та завершення теж мають claim keys.

Передача: неспоряджений предмет → offer одержувачу до 4 клітин → блокування предмета для інших ресурсних дій → accept протягом 30 с, повторна перевірка присутності/дистанції/власника → атомарне переміщення того самого ID зі зміною owner. Прийнята/прострочена offer більше не виконується. Самому собі передати не можна.

SQLite: `rooms(id,snapshot)`, `sessions(token,room,player)`, `operations(room,player,op,request,response)` з унікальним PK, `migrations(version)`. Для ресурсної команди snapshot і operations записуються в одній BEGIN IMMEDIATE транзакції. Той самий op з іншим payload відхиляється, той самий запит повертає попередню відповідь. Steer не записує кожен крок руху в durable operations; він не створює предметів і має обмежений час дії.

Бойовий snapshot checkpoint кожні 5 с; при аварії можлива втрата до 5 с неприв’язаного до команди бою, але не половини передачі/покупки. Дані БД не входять до Git. Збереження локального режиму має version=2; legacy key v1 не видаляється. Імпорт перевіряє схему/предмети та дозволений лише для соло; це не криптографічний захист локальної гри.

Recovery token — bearer-credential тимчасової кімнати, не повноцінний акаунт. Production потребує авторизації, обмеження часу життя сесій, резервних копій, аудиту, тестів перезапуску під навантаженням і стабільного HTTPS endpoint. Їх ще немає, тому публічну MMO-економіку не заявлено.

## Перевірки й відомі межі

Автоматично перевіряються формули, стани, шлях навколо перешкод, недоступність боса за ґратами, доступність інтерактивних точок, прогресія, предмети/порівняння/передачі, одноразові нагороди, голосування, телеграфи й міграція. Інтеграційний тест використовує реальні sockets двох і далі восьми незалежних клієнтів та серверний процес, а не обмін декоративними повідомленнями. Через браузер перевірено дві незалежні сесії, екран вибору, мобільне компонування 390×844 та карту. Фізичні телефони/8 одночасних браузерів/масове навантаження не перевірялися.

Немає: глобального відкритого MMO, P2P-ринку, гільдій, інших регіонів, повних 8-напрямкових наборів анімацій, особливих моделей усіх спеціалізацій, окремих мальованих діалогових портретів, гарантовано рівного класового балансу та серверного офлайн-фарму. Спрайти мають 4 бойові пози, двокадрову ходьбу та віддзеркалення; для фінальної анімації потрібно більше кадрів і напрямків. Ці межі не приховані за меню.
